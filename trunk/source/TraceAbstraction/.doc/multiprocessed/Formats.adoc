= Multi-process trace abstraction: content formats
:toc:

== Names of letters and locations

* *Letter* (`LetterNaming`): `e<id>` in every message (ATS_V2 automata and the words of JSON_V1). `<id>` is the
  serial number of a `CodeBlock` or the id of an `AbstractIcfgTransition` (other letter types throw). The reader looks
  the id up among its own letters and throws if it is unknown or not canonical (leading zeros). The fingerprint check
  guarantees that all sessions have the same edges under the same ids.
* *Full letter name*: `e<id>:<text>`, where `<text>` is the letter's `toString` without line breaks. It was the
  message form until Phase 5 (ATS_V1); the reader still accepts it and throws if the text differs from its own letter.
  The fingerprint prints full names, so it also covers the text of every edge (`toString` alone is not unique: every
  goto prints `goto;`).
* *Location* (`LocationNaming`): `<procedure>::<debugId>`.

Both rely on a deterministic frontend: equal programs give equal serials and debug ids in every process. The
fingerprint in `ready.json` checks this.

== ATS_V2: automata

ATS with `e<id>` letters; ATS_V1 (Phases 2 to 5) is the same with full letter names and is still read. Both use the
extension `ats`. Printed with `AutomatonDefinitionPrinter.toString` (no header, no timestamp) and parsed with
`AutomataScriptParserRun` + `AutomataDefinitionInterpreter` (`AtsCodec`).

* `ABSTRACTION`: states `q<n>@<location>`, only the program point. The receiver gives each state a don't-care
  predicate at its own location; states stay distinct even at the same location.
* `INTERPOLANT_AUTOMATON`: states `q<n>#<formula>`, the predicate's formula in SMT-LIB (`toStringDirect`) over the
  program variables. The receiver parses it with `PredicateParsingWrapperScript` and `TermParseUtils.parseTerm` and
  unifies it with a `PredicateUnifier`.
* `n` comes from a breadth-first search from the initial states that visits the outgoing transitions of a state
  ordered by letter name (return transitions then by the number of the hierarchical predecessor); unreached states
  come last, ordered by name. For a deterministic automaton such as the initial abstraction the numbering is
  canonical, so the print is a fingerprint.
* The printer quotes names but escapes nothing; `AtsCodec` escapes `"` and `\` itself, and the lexer turns them back.
* An automaton without call and return letters prints as `FiniteAutomaton`.
* The alphabet of every parsed automaton must be the receiver's alphabet; any unknown letter, location or formula
  throws. Under `-ea` each print is parsed back and compared.

== JSON_V1: everything else

Gson (`com.google.gson`), strict: every message object has `"format": "JSON_V1"`; a wrong format, an unknown field, a
missing required field, a `null` in a list or map, or an unknown enum value throws (`JsonCodec`).

*Words* are two lists of the same length: `word` (letter names) and `nesting`. `nesting[i]` is the position of the
matching return of a call at `i`, or of the matching call of a return at `i`; `-1` is internal, `-2` a pending call,
`-3` a pending return. The reader checks that the nesting is well formed and fits the letter kinds (`WordCodec`).

[cols="1,3"]
|===
| Type | Fields

| `COUNTEREXAMPLE`
| `{job, generation, word, nesting, pathProgramCount}`; `pathProgramCount` counts how often the coordinator handed
  out a word of this path program, this one included

| `RESULT`
| `{job, generation, status: UNSAT\|SAT\|UNKNOWN, automatonType?: FLOYD_HOARE\|ERROR, word?, nesting?, reason?}`.
  A TA worker always sets `automatonType`; SAT carries the word. The synthetic result for a gone TA session is
  exactly `{job, generation, status: "UNKNOWN", reason: "SESSION_LOST"\|"SESSION_CRASHED"}`.

| `CANCEL`
| `{job}`

| `PROOF_ANNOTATION`
| `{generation, invariants: {location: formula}}`

| `VERDICT`
| `{verdict: TRUE\|FALSE\|UNKNOWN, decidedBy: kind, evidence: {word?, nesting?, invariants?}}`

| `EXCEPTION`
| `{kind, exceptionClass, message?, stackTrace}`

| `RETIRED`
| `{reason}`
|===

Files without `format`: `ready.json`, the `.ref.json` of a blob (`{sha256, size}`).

=== statistics.json

`{format: "JSON_V1", kind, sessionId, end: SHUTDOWN|TIME_LIMIT|DONE|EXCEPTION, wallTimeMs, counters, ultimate}`.
`ultimate` is Ultimate's flattened benchmark data (non-numbers as strings). Counters:

* TA_WORKER: `jobs`, `jobsUnsat`, `jobsSat`, `jobsUnknown`, `jobsSkipped`, `jobsStopped`, `abstractionsInstalled`,
  `traceCheckTimeMs`, `automatonTimeMs`, `maxJobTimeMs`;
* COORDINATOR: `jobs`, `refinements`, `cancels`, `abstractionsPublished`, `lostTaSessions`, `crashedTaSessions`,
  `refinementTimeMs`, `searchTimeMs`, `idleTimeMs`, `abstractionSize`;
* WITNESS: `results`, `resultsSat`, `proofAnnotations`, `invariantsReported`, `invariantsDropped`, `witnessLevel`
  (3 with values, 2 without values, 1 target only, 0 none);
* FRONTEND: `packageBytes`, `serializeTimeMs`, `locations`, `edges`.

== PACKAGE_JSON_V1: the program package

The `PROGRAM_PACKAGE` message (extension `json`, normally a blob): the ICFG that TraceAbstraction receives (the
IcfgBuilder's output, with its large block encoding), written by
`ProgramPackageWriter` as the record `ProgramPackage` with `"format": "PACKAGE_JSON_V1"` and read as strictly as
JSON_V1. Every list has a fixed order, so that equal programs give equal bytes (three JVMs give byte-identical
packages, also for `aws_byte_cursor_read_harness`).

* `identifier`: the identifier of the ICFG.
* `logic`: the SMT logic of the script that built the ICFG.
* `declarations`: `declare-sort`, `define-sort`, `declare-fun` and `define-fun` commands in declaration order, the
  order in which they replay (a `define-fun` may use earlier symbols). Only what the ICFG uses: the sorts and functions
  of the edge formulas, the axioms and the program-variable constants, closed under defined-function bodies, so
  nothing the solver declared before for other purposes is included.
* `functions`: the used SMT functions that are program functions (e.g. Boogie functions such as `~bitwiseAnd`);
  predicates over them need them in the symbol table.
* `axioms`: the closed axiom formula.
* `globals` (with their old variables), `constants`, and `procedures` (locals including parameters, in/out parameters,
  modifiable globals). A variable is `{identifier, sort, termVariable, defaultConstant, primedConstant}`; elsewhere a
  program variable is referred to by the name of its term variable.
* `locations`: `{procedure, debugId, hash, outgoing, incoming}`, named `<procedure>::<debugId>`; `hash` is the hash code
  of the writer's debug identifier, `outgoing`/`incoming` the edge ids in their order at the location.
* `special`: the initial, error, entry, exit and loop locations and the locations of interest, each list in the
  iteration order of the writer's collection, and `detached`: `{procedure, debugId, hash}` of the special locations
  that are not program points (they have no edges). The IcfgBuilder removes unreachable code from the program points
  but keeps its error locations (e.g. a `reach_error()` after a `longjmp`), and TraceAbstraction counts them, so the
  package keeps them as well.
* `freshVariables`: the state of the script's variable manager (counter per basename, basename per term variable), so
  that the reading process constructs the same fresh names and no fresh variable clashes with one of the package.
* `edges`, ordered by id: `{id, kind: INTERNAL|CALL|RETURN, source, target, transFormula, withBranchEncoders?, call?,
  overapproximations?}`. `overapproximations` are the reasons of the edge's `Overapprox` annotation: a counterexample
  through such an edge does not prove a violation, also in a session started from the package.
  The id is the CodeBlock serial, so `e<id>` letters match. The summary edges of calls to procedures with an
  implementation are left out: an interprocedural analysis never uses them, and as plain internal edges they would be
  shortcuts that havoc the callee's effects (multi-process sessions therefore require the interprocedural analysis). `transFormula` is the edge's formula (for a call the
  local-variable assignment, for a return the assignment of the return values): `{formula, inVars, outVars, auxVars,
  branchEncoders, nonTheoryConsts, infeasibility}`, formula in SMT-LIB with lets.

*Same behaviour as from C:* every collection that TraceAbstraction iterates is written in the writer's iteration
order and read back in that order (symbol table, procedures, program points, edges of a location, special locations,
and the variable maps and sets of a transition formula, which the reader keeps as linked collections via
`TransFormulaBuilder.constructKeepingCollections`); read locations hash like the writer's (`PackageDebugIdentifier`);
the variable manager continues from the writer's state. Then a session started from the package sends byte-identical
SMT queries to the solver (checked on the trace checks of `ki-stack-mutual-safe`). Without this, fresh variables got
other names and collections another order, and one hard trace check took 4 times as long.

*Reading* (`ProgramPackageReader`, wrapped by the source plug-in `de.uni_freiburg.informatik.ultimate.source.programpackage`
of the toolchain `AutomizerPackage.xml`): the script is built like the IcfgBuilder's, from the session's IcfgBuilder
SMT settings; its logic must be the package's `logic`. The declarations replay in package order, formulas are parsed
with their variables bound and only the lets expanded (no other normalization), and the edges are generic
`IcfgInternalTransition`/`IcfgCallTransition`/`IcfgReturnTransition` with the package ids. Writing the read ICFG
gives the package's bytes again (checked under `-ea`, in `ProgramPackageReaderTest`, and by every package-mode run,
whose fingerprints are hashes of re-serializations). The source plug-in registers an identity backtranslator and
annotates the ICFG, its locations and edges with a location naming the package file, so that the results of the
coordinator are reported on the level of the ICFG.

*Fingerprint:* the SHA-256 of the package bytes, for every kind (`MultiProcessSession.fingerprint`). FRONTEND hashes
the package it sends; every other kind serializes the ICFG it runs on: WITNESS and C-mode sessions their C-built ICFG,
package-mode sessions the read one.

== YAML_V1: the witness

A YAML witness, format 2.x, as the WitnessPrinter writes it: a `violation_sequence` for FALSE, an `invariant_set` for
TRUE.
